# Data Manager — інтегрований модуль

Маршрут оболонки: `/DataManager_Ryzhenko`.

Модуль оновлено з `Gr1sTo/data-manager-ui2`, коміт
`cc4807324f97b281d82a46a7abbf6261fa88640c`.
Використовуються наявні React 19 і Tailwind 4 оболонки. Окрема точка входу
`main.jsx`, глобальні стилі самостійного застосунку та його Vite-конфіг
не переносяться.

## Підключення API

Браузер звертається до власного resource route модуля
`/DataManager_Ryzhenko/api/:service/*`. Він працює через сервер React Router
як у development, так і після production-збірки. Dev-проксі Vite не потрібен.

| Сервіс | Префікс у браузері | Адреса сервера за замовчуванням |
| --- | --- | --- |
| Документи | `/DataManager_Ryzhenko/api/document` | `http://77.47.192.6:6066/api/v1` |
| Температурні вимірювання | `/DataManager_Ryzhenko/api/relational` | `http://77.47.192.6:6024` |
| Демонстраційні файлові дані | `/DataManager_Ryzhenko/api/file` | `http://77.47.192.6:6023/api/file` |

Адреси можна перевизначити **в оточенні процесу сервера оболонки**:

- `DATA_MANAGER_DOCUMENT_API_URL` — включно з `/api/v1`;
- `DATA_MANAGER_RELATIONAL_API_URL` — корінь сервера, без `/api/temp-control/records`;
- `DATA_MANAGER_FILE_API_URL` — включно з `/api/file`.

Це серверні змінні, а не `VITE_*`. Після їх зміни потрібно перезапустити
сервер оболонки. За відсутності змінних використовуються адреси з таблиці;
змінювати Dockerfile або інші сервіси для цього оновлення не потрібно.

Оболонка має мати мережевий доступ до трьох API. Проксі пересилає лише
маршрути й методи, потрібні цьому модулю. Ціль не задається браузером;
cookies не пересилаються, а `Authorization` передається лише Document API.
Відповіді не кешуються, перенаправлення не виконуються. HTTP-статуси API,
зокрема `401`, `403`, `404` і `422`, зберігаються. Таймаут upstream — 15 секунд.

## Поведінка

- Документи: вхід, профіль і ролі, серверні фільтри/пагінація, створення,
  редагування та видалення; адміністратору доступне керування користувачами.
- JWT зберігається лише в `sessionStorage` браузера. Під час SSR сервер
  не читає браузерне сховище та не зберігає спільну JWT-сесію. `401` очищує
  сесію; повторний вхід завантажує документи без оновлення сторінки.
- Реляційний API: запит за часовим діапазоном, останній запис датчика,
  створення температурного вимірювання. Демонстраційні таблиці не використовуються.
- Файловий режим зберігає чинний контракт demo API на порту `6023`.
  Зміни тестових даних зберігаються за правилами наявного контейнера.

## Перевірки

Із каталогу `obolonka`:

```bash
npm ci
npm run build
node --test app/routes/DataManager_Ryzhenko/tests/*.node-test.mjs
```

Тести авторизації й API використовують змодельовані відповіді, а тести
проксі — локальні HTTP-сервери. Вони не змінюють дані реальних API.
Суфікс `.node-test.mjs` відокремлює ці перевірки Node.js від наявного Vitest.

У початковій версії оболонки `npm run typecheck` уже має 11 помилок в інших
модулях; їхній перелік після інтеграції не змінився. Загальний Vitest запускає
132 успішні тести, але suite `iotGateway` потребує відсутнього
`@testing-library/react`. Ці наявні проблеми не виправлялися в межах інтеграції.

Зміни інтеграції обмежено цим каталогом і реєстрацією одного власного
API-маршруту в `app/routes.ts`. Інші модулі, глобальні стилі,
залежності та Docker-конфігурацію не змінено.
